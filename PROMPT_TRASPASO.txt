ACTUALIZACIÓN 2: DESPLIEGUE 100% VERCEL YA IMPLEMENTADO
-------------------------------------------------------

El usuario eligió convertir todo a Vercel (sin Render/Railway) manteniendo login,
admin y persistencia en Neon. Ya está hecho:

- `server/app.ts` exporta la app Express sin `app.listen`; `server/index.ts` es la
  entrada local y `api/[...path].ts` es la función serverless catch-all de Vercel.
- Inicialización perezosa de Neon por instancia (`ensureDb()`), pool pequeño
  (`PG_POOL_MAX`, por defecto 3) y `allowExitOnIdle` para serverless.
- CORS con allowlist + localhost + `*.vercel.app`; en Vercel todo es mismo origen,
  así que `VITE_API_URL` debe quedar vacío.
- Endurecimiento: `trust proxy`, comparación bcrypt de relleno para emails
  inexistentes, rol admin verificado en BD en cada petición, 413 para cuerpos
  demasiado grandes, rate limiting y validación estricta.
- `vercel.json` con build de Vite, salida `dist/`, `maxDuration: 30` para `api/**`
  y un rewrite `/api/:path*` -> `/api/[...path]`. Este rewrite es imprescindible:
  el catch-all de una función Node de Vercel solo captura un segmento y, sin él,
  `/api/auth/login` y el resto de rutas anidadas devuelven 404.
- Code splitting: las pestañas y paneles se cargan con `React.lazy`/`Suspense`, y
  cada nivel del currículo (A1/A2/B1/B2) vive en su propio chunk bajo demanda.
  El bundle inicial bajó de ~1 MB a ~254 kB y ningún chunk supera los 500 kB.
- Tests: `npm test` ejecuta `tests/security.test.ts` (unitarios) y
  `tests/api.test.ts` (integración real contra Neon con usuarios temporales).
  `npm run smoke:prod -- URL` verifica un despliegue real de Vercel, incluidas
  las rutas anidadas `/api/*`.
- `npm run build`, `npm run typecheck:server`, `npm test` y `npm run lint` pasan.

Variables necesarias en Vercel: `DATABASE_URL` y `JWT_SECRET` (mínimo 24 caracteres).
Opcionales: `CORS_ORIGIN` para dominio propio y `PG_POOL_MAX`. No definir `PORT` ni

6. MAPA DE TEMAS Y NIVELES
---------------------------

Usa esta guía para que el contenido sea coherente:

A1:
1. TO BE: identidad, nacionalidad, edad, sentimientos, ubicación.
2. Present Simple: rutina diaria, horas, trabajo/estudio, aficiones.
3. Present Continuous: acciones ahora, ropa, clima, actividades temporales.
4. Present Simple vs Continuous: hábitos vs ahora, marcadores de tiempo.
5. Past Simple básico: was/were, verbos regulares, ayer, lugares, eventos simples.

A2:
1. Past Simple irregular + did: fin de semana, anécdotas, preguntas.
2. Past Continuous: interrupciones, accidentes, escenas.
3. Futuro: planes de viaje, citas, decisiones espontáneas.
4. Modales: habilidad, obligación, reglas, trabajo/estudio.
5. GET: transporte, cambios, obtener, entender.

B1:
1. Present Perfect: experiencias, logros, vida.
2. Present Perfect vs Past Simple: entrevistas, timelines, noticias.
3. Present Perfect Continuous: acciones en curso, síntomas, proyectos.
4. First/Second Conditional: decisiones, consejos, hipótesis.
5. Modales de deducción: especulación, evidencia, fotos.

B2:
1. Third Conditional: arrepentimientos, decisiones, post-mortem de proyectos.
2. Passive Voice: procesos, informes, comunicación corporativa.
3. Reported Speech: reuniones, mensajes, rumores.
4. Phrasal Verbs de negocio: reuniones, seguimiento, negociación.

11. FASE 5: DESPLIEGUE 100% EN VERCEL
------------------------------------

Implementado. El proyecto se despliega como un único proyecto de Vercel:

- Frontend React/Vite -> `dist/`.
- API Express -> `api/[...path].ts` (función serverless catch-all).
- Base de datos -> Neon con `pg` y pool limitado por instancia.
- Frontend y API comparten origen: `VITE_API_URL` vacío y CORS sin configurar.

Pasos:
1. Subir el repo a GitHub.
2. Importar el repo en Vercel (detecta `vercel.json`).
3. Framework preset: Vite. Build: `npm run build`. Output: `dist`.
4. Variables de entorno en Vercel:
   - `DATABASE_URL` (cadena de Neon, preferiblemente pooled, con `?sslmode=require`)
   - `JWT_SECRET` (aleatorio, >= 24 caracteres; nunca `secret123`)
   - Opcional: `CORS_ORIGIN` para dominio propio
   - Opcional: `PG_POOL_MAX` (por defecto 3)
   - NO definir `PORT` ni `VITE_API_URL`
5. Deploy.
6. Verificar `https://tu-proyecto.vercel.app/api/health` -> `{"ok":true}`.
7. Probar registro, login, persistencia y panel admin desde el dominio de Vercel.

Para promocionar un admin, ejecutar en Neon:
`UPDATE users SET role = 'admin' WHERE email = '...';` y volver a iniciar sesión.

No hardcodees localhost en producción.
